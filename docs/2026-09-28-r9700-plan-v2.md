## The fp8 question

AMD's fp8 number is real. On this card I measured 371 TFLOPS for register-resident
fp8, against f16 at 184 and s8 at 356. The larger AMD figures assume 2:4
sparsity, which RADV does not expose. A real GEMM feeds its operands through LDS,
and on this driver that reaches ~55% of the register peak: f16 101 TF, s8 169 TOPS.
LDS-fed fp8 has not been measured.

fp8 e4m3 is **lossy** for this model's stored values. It represents odd integers
exactly only up to ±16, while Q6_K weights span −32..31 and q8_0 K/V span ±127.
It is excluded for weights and for K/V operands. It stays a candidate only for
activation operands, and only behind the numerics gates. The exact 8-bit path is
s8.

## Targets

Savings re-derived from D0: D1 −4.2 ms (lm_head 1.65 → ~0.25, x3), D2 −2,
D3 −1.5 to −2, D4 −3.5, for ~11–12 ms in total. From the quiet-window steps
(73.0 / 63.9) that lands at ~61.5 / ~52.5 ms, so the t/s targets hold, and
70k sits on the edge.

| metric | now | **target** | stretch |
|---|---:|---:|---:|
| verify+draft step @ 176k, n_max 3 | ~73 ms | **≤ 62 ms** | ≤ 55 |
| verify+draft step @ 70k | ~64 ms | **≤ 53 ms** | ≤ 47 |
| → decode @ 176k on depth.sh (3.41 tok/step) | 46.8 | **≥ 55** | ≥ 62 |
| → decode @ 70k on depth.sh (3.17 tok/step) | 49.5 | **≥ 60** | ≥ 67 |
| pooled acceptance (15 prompts) | 0.706 | ≥ 0.696 (±0.01 gate) | — |
| pp2048 @ d0 | 1,507 | **≥ 1,700** (P0 no-go; was 2,200) | ≥ 1,850 |
| pp2048 @ d16384 | 1,321 | **≥ 1,480** (was 1,900) | ≥ 1,600 |
| pp512 @ d131072 | 712 | **≥ 850** (was 1,000) | ≥ 1,000 |

Beating the stretch on decode needs D5 to raise tokens per step without paying
the verify cost that killed n_max 4 (see D5). The prefill target arithmetic: a
512-token ubatch at 2,200 t/s is 233 ms. Minus ~40 ms of non-GEMM work, the GEMM
must average **~135 TOPS over the whole model's shape mix**, while today it runs
65–86 TF depending on shape.

## Gates (in addition to the v1 Gates)

- **Output identity, tie-aware.** Speculation is not output-identical on this
  model: n_max 2 and 4 diverge from each other and from no-spec
  (FINDINGS "Speculative decoding is not output-identical here"). A draft change
  alters accepted lengths, so verify-batch rows move and near-ties can flip.
  Gate: `harness/verify.py --tie-ratio 1.2` against the pre-change build, and a
  divergence passes only at a near-tie.
- **Acceptance:** pooled over ≥ 10 prompts, ±0.01 of the pre-change build.
  Prompts not used to choose any parameter (D1's vocabulary) must include chat,
  prose, multilingual and an image prompt.
- **Numerics:** any 8-bit arithmetic (P1, P2) must pass PPL (ΔPPL ≤ 0.2%) and
  decode KLD. Prefill FA also needs the acceptance gate.
- **VRAM:** peak is 32,581 of 32,624 MiB (43 MiB free). Any new resident buffer
  names its source before work starts. Peak is re-measured during a 176k prefill
  **plus an mmproj image request at depth** (the clip compute buffer is 248 MiB).
- **mmproj regression:** image encode time (1024² at ctx 262144; 257 ms on
  integrate) for any GEMM or FA change.
- End-to-end t/s and ms/step A/Bs run **only in the main session**, in one quiet
  window (loadavg < 2), back to back, decode builds run twice.

## Decode tasks

**D0: one-run budget (main session).** At 70k and 176k, in one server run:
- per-graph GPU time for verify and each draft (perf logger);
- host time split into draft-phase host vs draft-phase GPU, and verify host (R5's
  `GGML_VK_STEP_TIMING` / `LLAMA_DECODE_TIMING`);
- **the verify graph at n=5 vs n=4, per op**, including the GDN recurrent-state
  rollback path (`server-context.cpp`, draft.size() > n_rs_seq).

Output: the budget table with measured numbers. Every target and every D-task
estimate is re-derived from D0 before dispatch. **[DONE 2026-09-28]** See the
budget section above; D5's literal gate fails (+3.5 ms), but see the n_max 4
result there.

**D1: reduced-vocabulary draft head.**
- Drafts take the argmax after top_k(10) with p_min 0 (`common/speculative.cpp`
  ~1399, `common/common.h` p_min default), so only the top-1 id matters.
- **At load, permute `output.weight` rows** so the V draft tokens come first. The
  draft head is then a zero-copy view of the first V rows, and ids are mapped back
  after readback.
- No new buffer: the main lm_head reads the permuted tensor with an id map on the
  logits.
- Choose V (32k / 64k) from a corpus **disjoint** from the gate prompts.

Interface: `--spec-draft-vocab N` (0 = full). Acceptance: identity (tie-aware)
and acceptance gates; draft GPU time −1.2 ms or more per draft. Kill: acceptance
loss > 0.01 at the best V, or any VRAM increase.

**D2: GPU-resident draft chain.** R7 built it (`r9700-r5-decodehost` @ `2fc6d40aa`,
opt-in `LLAMA_MTP_GPU_CHAIN=1`). It needs embeddings for the V draft tokens only:
64k ≈ 270 MB, 32k ≈ 135 MB. **Before starting, name the VRAM source**, for
example a smaller compute buffer from a measured smaller ubatch, or storing the
subset from the permuted `token_embd`. No source means no D2. The honest win is
the draft-phase host time D0 measures (R7 implies ~2 ms, not 8). Acceptance:
identity gate; decode ms/step −2 ms or more. Kill: less than −1.5 ms, or no VRAM
source.

**D3: verify-side host time.**
- Record the next graph while the GPU runs.
- Move sampling bookkeeping off the critical path.
- Graph reuse, only where R5's bound (≤ 0.35 ms) does not already rule it out.
- Async upload is known slower (R5); don't retry it.

Acceptance: verify host ms −2 ms or more, bit-identical. Kill: less than −1 ms.

**D4: verify small ops (~6 ms).**
- GDN snapshots written directly into the cache, which removes the CPY and fuses
  the gather (1.2 ms).
- Split rows in the 5120-wide RMS_NORM_MUL (0.78 ms).
- RMS_NORM→SCALE activated via `keep_pattern` while keeping SILU_MUL fused.
- Fuse the GDN elementwise chains.

Acceptance: other ops ≤ 3 ms per verify; test-backend-ops on the touched ops;
decode KLD. Kill: less than −1.5 ms after two designs.

**D5: more tokens per verify (conditional).** The n_max 4 loss was **verify cost**,
not draft cost: 3.80 tokens in 84.3 ms against 3.29 in 70.4 (TG-4). D5 runs only
if D0 shows the n=5 verify costs ≤ n=4 + 2 ms, or if D0 identifies the extra
cost (for example the recurrent-state rollback) and a fix for it is built and
measured first. Then: an n_max 4–6 sweep, then a tree-verification spike that
prices GDN state forking per branch (48 layers) before any build. Kill: the fix
leaves n=5 more than 2 ms above n=4.

**D6 (new, from D0): merge the MTP catch-up into the first draft decode.**
- Each step runs `process()`, an n=4 catch-up decode on the draft context over
  every verify row, at 1.4–2.1 ms GPU + ~1.1 ms host. Then `draft()` runs 3
  n=1 decodes.
- Instead, defer the catch-up for verify batches (not prompt ubatches) until
  `draft()`. There, decode the **accepted** rows plus the first draft row
  `(id_last, pending_h)` as one batch, with logits only on the last row.
- Drafts must be identical, and only the pairing/KV bookkeeping moves
  (`common/speculative.cpp` ~1484–1700 and the server's seq_rm after
  acceptance).

Estimate: −1 decode call (~1 ms host) and ~−1.5 ms GPU per step. Kill:
< −1.5 ms per step.

## Prefill tasks (after decode)

**P0: 8-bit ceiling microbenchmarks** (`harness/wmma_peak/`, no llama.cpp).
LDS-fed GEMMs, applying the two RDNA4 rules (no conditional prefetch; check LDS
bank mapping):
- (a) s8 with a Q6_K-shaped epilogue: int32 accumulate per 16-K WMMA, integer
  multiply-add by the sub-scale, one float per 256-K super-block. The prior int8
  kernel capped at 61 TF with a per-32 **float** epilogue; this one is
  per-16 but **integer**. This is the deciding measurement.
- (b) the cost of quantizing activations to s8.
- (c) f16 at BK=64 as the reference.
- (d) fp8 activations × f16-converted weights: only if (a) fails.

Measure on the **model-weighted shape mix**:
- 17408×5120 (×2 with the swiglu fusion);
- 5120×17408;
- the attention and GDN projections, including m=1024 and 6144/10240/12288.

Go/no-go: a weighted effective rate ≥ 135 TOPS including activation
quantization. Below that, re-derive the prefill targets before P1.

**[DONE 2026-09-28, NO-GO]** (`results/p0/p0-s8-20260928T185151Z.txt`,
perf-lab 184db02). Weighted TOPS at N=512, including quantization:

| design | weighted |
|---|---:|
| exact s8 on real Q6_K | 77.5 |
| exact s8, pre-expanded | 85.2 |
| s8 with no sub-scale (a requantised format, which the rules forbid) | 126.9 |
| f16 double-buffered | 90.6 |

The per-16 integer epilogue costs about as much as the WMMA. Activation quant
is ~1%. f16 single-buffer LDS reaches 111.5 TF on 17408x5120, against 101.4
double-buffered. **P1 becomes an f16 port of the single-buffer structure.**
Re-derived: ~24.3 G weights x 2 x 512 = 24.9 TFLOP per ubatch. Today that is
~300 ms of GEMM (~83 TF) plus ~40 ms of other work at d0. At ~100 TF weighted
the ubatch is ~290 ms, so **pp2048 d0 target ≥ 1,700 (stretch 1,850)** replaces
2,200. The d16384 target becomes ≥ 1,480. The pp512 @ d131072 target of 1,000
needs −207 ms per ubatch: P1 ~−50, P2 ~−70, P3 ~−20 leave it at ~850, so
**≥ 850** is the re-derived target.

**P1: s8 Q6_K GEMM** (the design P0 picked), a new module beside
`mul_mm_q6k_rdna4_f16` that keeps split-K, the n-fast order and the swiglu fusion.
Acceptance: MUL_MAT and fusion tests; both numerics gates; mmproj check;
weighted ≥ 135 TOPS; pp2048 d0 at the P0-derived target. Kill: weighted below 110
TOPS after two designs.

**P1 result (`r9700-p1-f16sb` f9968c35f):**
- The serving kernel already had the single-buffer structure. Ablation at
  128x128: loads cost ~19 TF, dequant ~6.
- The lean dequant plus a 4x-unrolled K loop (11 weight loads per 4 steps
  instead of 24) takes the weighted mix from 84.1 to 87.8 TF.
- pp2048 d0 goes 1,521 → **1,577 (+3.7%)**. That is under the +5% kill line,
  but kept as the default (`GGML_VK_NO_Q6K_LEANQ=1` reverts it).
- 12288x5120 regressed −7% after losing the 128x256 tile, so route it back.

**P1b (next):** cooperative, coalesced staging of raw Q6_K super-blocks into
LDS, aimed at the ~19 TF load gap.

**P2: prefill FA to ≥ 100 TF.**
- 64-byte V rows (R3: ~2 of 20.9 ms).
- s8 QKᵀ only after a microbenchmark on the current `_rs` kernel. PP-2 (int8 FA,
  12.3 vs 15.1 TF) and WS1b were kills, but on the old kernel.
- **fp8 PV is dropped** (q8_0 V spans ±127). PV stays f16.

Acceptance: FA tests; both numerics gates; acceptance gate; mmproj check;
pp512 @ d131072 at the derived target. Kill: below 90 TF after two designs.

**P3: prefill small ops at depth** (~85 ms per ubatch at 131k). Profile with
`prefill_profile.sh`, fuse the largest. Chunked GDN prefill only if it exceeds 5%.
Kill: less than −20 ms per ubatch.

**P4: re-sweep** ubatch 512/1024/2048 and n_max with the final kernels; FINDINGS entry.

## Order, bundling, execution

D0 → D1 → D2 → D3 (serial, same files) ∥ D4 → D5 (conditional) → P0 → P1 ∥ P2 → P3 → P4.

| agent | tasks | why |
|---|---|---|
| main | D0, every end-to-end A/B, merges, gate runs, VRAM and mmproj checks | measurements serialized and quiet |
| A | D1 → D2 → D3 | all touch llama host code (`llama-context`, `llama-graph`, `llama-kv-cache`, `common/speculative`); serial in one agent, split at the 40-turn cap |
| B | D4 | ggml-vulkan only; no file overlap with A |
| C | D5 | only if D0 opens it |
| D | P0 → P1 | the microbenchmark decides P1's design |
| E | P2 | independent shader |

≤ 3 agents at once. Each has its own scratch prefix, never runs depth.sh, and runs
every GPU command under `gpu_lock.sh`.

## Constraints carried forward

- ACO: `x=0; if (ok) x=load` serializes the load. Use unconditional clamped loads.
- Compute LDS bank mapping for staging stores before other tuning.
- V's q8_0 scale runs along head_dim, so int8 or fp8 PV with a post-MMA scale is invalid.
- New variants go in separate shader modules with a `GGML_VK_NO_<NAME>=1` switch.
- One greedy prompt swings acceptance ±0.04. Judge it pooled.
- Decode A/Bs only in a quiet window. Sibling CPU load cost 20% before.
- The verify GEMV is at ~95% of DRAM and Q6_K MMVQ is a loss. Leave both.
