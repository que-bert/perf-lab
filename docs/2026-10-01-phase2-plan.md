# Phase 2 plan: spread the Qwen3.8-27B gains to every model and quant (2026-10-01, rev 3)

rev 3 = rev 2 + devil's-advocate review (10 objections, all accepted; see "DA changes" at the end).

## Mission

Turn the fork tuned for one job (Qwen3.8-27B Q6_K, MTP, R9700, Vulkan) into a general runner that:

1. **never lowers Qwen3.8-27B throughput**, decode (tg) or prefill (pp), at any depth;
2. is **at least as fast as upstream llama.cpp on the zoo** (the target models below), and correct on all of them;
3. is **very fast on the two primary models**, Qwen3.8-27B and MiniCPM5-2B;
4. **just works** with any GGUF: no per-model flags, no crash or wrong output on a model it was never tuned for.

RDNA3 is out of scope. Qwen4-27B is prepared for (W9), not planned against.

## Invariants and how they are measured

Statistic for every A/B: k interleaved ABAB pairs, mean difference with a one-sided 90% bound; k is set from
the measured run-to-run variance of that axis (W0 measures it), not fixed. A loss counts only if the bound
excludes zero AND a re-run confirms it.

- **I1, Qwen3.8 never-regress.** Axes: decode 70k/176k, prefill 70k/176k, pooled 37 prompts, 32.5k server
  prompt. Two references: (a) the current integration tag, per merge; (b) a fixed **integrate16 anchor** that is
  never re-baselined, per integration tag, with a total drift limit of 0.5% on any axis. (b) stops small
  per-merge losses from adding up. Run through the **flagless auto-config path** as well as the explicit
  serving flags (W4), so preset changes cannot bypass it.
- **I2, MiniCPM5-2B never-regress.** Same method on MiniCPM's axes once W2 sets its baseline; same anchor rule.
- **I3, correctness.** Zoo smoke: every target loads, generates 64 tokens greedy; text compared with upstream
  over the first 32 tokens, beyond that by KLD against per-model reference logits (made in W0).
- **I4, fork >= upstream on the zoo.** Checked once per rebase/integration tag against an upstream build at
  the same base; a loss beyond the axis tolerance, confirmed on re-run, is a bug.

## Gate tiers and GPU budget (one GPU, shared with gaming)

| tier | when | contents | GPU time |
|---|---|---|---|
| T1 | every merge | focused op tests, zoo smoke (I3), short I1 (70k decode+prefill, 32.5k prompt, k from W0) | ~30-40 min |
| T2 | every integration tag | full I1 incl. anchor + auto-config path, I2, gates4, pooled texts | ~2-2.5 h |
| T3 | every rebase | T2 + I4 vs fresh upstream build | ~4 h |

Every GPU run samples VRAM and the processes holding the R9700 during the run (not only at start); a run
where anything else appears is void. `gpu_lock.sh` refuses to start while another process holds the card.

## Workstreams, in order

### W0. Harness, noise and fork-path inventory (~2 days, first)
- `harness/model_profile.sh`, `harness/model_quality.sh` (PPL, KLD vs per-model upstream reference logits,
  acceptance), `harness/zoo_smoke.sh` (I3), the in-run GPU contention sampler.
- Measure run-to-run variance per axis per primary model and set k for I1/I2.
- **Fork-path inventory**: one table of every fork path (79 commits, 30 `GGML_VK_NO_*` switches, RDNA4
  detection) with its engagement guard (arch, quant, shape, env). Plus a zoo run with every switch off, which
  must equal upstream in text and speed: that proves the fallback is upstream.
- Done when: profile, quality, smoke and variance exist for all targets on i16 and upstream at the same base;
  inventory table committed; references (logits) generated.

### W1 + W2 in parallel (primary models first)
- **W1, RB without regression (time-boxed 1 day).** Per-step host profile i16 vs rb at 16k/70k. If a cost is
  found, remove it or gate the new upstream path off the hot loop. If nothing is visible in STEP_TIMING in a
  day, re-measure RB-AB2 with W0's k: if the bound excludes zero, keep integrate16 as base and take upstream by
  cherry-pick; otherwise accept RB as base. Then tag `r9700-integrate17` (passes T2) and push.
- **W2, MiniCPM5-2B (~2-3 days).** Profile; make the fork's host-side work (graph reuse, fusions, prealloc,
  submit timing) engage on llama arch; n-gram/lookup drafting; Q4_K_M vs Q8_0 by quality and speed. Done when
  fork beats upstream on tg and pp by a confirmed margin, serving preset recorded, I2 baseline set.

### W4. Just-works serving (~2 days)
- **Presets pinned by identity**: auto-config picks MTP when the GGUF has nextn layers, plus KV types, ubatch,
  FA and draft settings. The 27B and MiniCPM presets are keyed by GGUF identity (arch + size + quant, or sha) and
  change only through I1/I2; other models fall back to per-arch presets. Explicit flags override.
- **Converter, not loader patch**: a standalone tool converts ollama-packed GGUFs (Gemma4 in-file towers,
  qwen35 rope/tensor-name variants) to upstream layout; the loader only prints a clear message naming it. No
  loader divergence to carry through rebases.
- **Validated-only fork paths**: guards from the W0 inventory tightened so a fork path engages only where it was
  tested; the all-switches-off zoo run stays in T3.

### W5. Gemma4-E4B (~2-3 days)
- Profile on the loadable (or converted) file: launch-bound decode, Q6_K 262k-vocab output head, per-layer
  embedding GET_ROWS, FA coverage at hsk 512 (FA320 SIGFPE is a known hole). Draft: E2B, n-gram, none.
- Done when fork >= upstream on tg and pp, gates pass.

### W6. Tuning (alongside)
- Kernel parameters per quant/shape on RDNA4 from W0 op tables, in an arch-gated table.
- Runtime config per model; winners become W4 presets (primary presets only via I1/I2).

### W3. Q4_K/Q5_K kernels (conditional, after W4)
- Does not touch the primary models as served (27B is Q6_K; MiniCPM is launch-bound), so it runs for the
  secondary models, or for a 27B Q4_K_M serving option if that is decided.
- 27B Q4_K_M decision first: finish its quality gates (row Q4E1 skipped them). If it is adopted, prefill
  (W8, -19% at 70k) comes before decode, because Q4_K_M already loses to Q6_K on pp.
- First step either way: W0 bandwidth report; skip if Q4_K/Q5_K GEMVs are within 10% of the Q6_K path.

### W7. MoE (Qwen3.6-35B-A3B) (~2-3 days)
- MUL_MAT_ID decode for n=1..5 x 8 experts on Q5_K/Q6_K/Q8_0; upstream prefill tiles; MTP via the host
  pipeline. Done when fork > upstream on tg and pp.

### W8. Q4_K/Q5_K prefill GEMM (conditional, see W3)

### W9. Qwen4-27B readiness (ongoing)
- Rebase every 2-3 weeks (T3). Fork paths keyed on tensor properties (W0 inventory). W0 + W4 make day 0 one
  command: profile, quality reference, preset.

## Maintenance rules
- **Switch retirement**: at each integration tag, a switch whose path has been default-on and gated for 2 tags
  is removed (code path kept, env check dropped). Switch count is reported per tag.
- **Release discipline**: serving binaries are tagged, built from a clean tree, `--version` recorded, previous
  tag kept for one-command rollback.
- Prompt/KV reuse with MTP on (cache hits skip prefill) is checked once in W4.

## Order
W0 -> (W1 || W2) -> W4 -> W5, W7 -> W3/W8 if decided; W6 alongside; W9 ongoing. Every merge passes T1; every
integration tag T2; every rebase T3.

## DA changes (rev 3)
1. Thresholds replaced by a variance-based statistic with re-run confirmation; 32.5k prompt added; W1 time-boxed.
2. Fixed integrate16 anchor with 0.5% total drift limit.
3. Gate tiers T1/T2/T3 with GPU budget.
4. I1/I2 run through the auto-config path; primary presets pinned by identity.
5. Primary models first (W1 || W2); W3 moved after W4 and made conditional; W8 before W3 if 27B Q4_K_M is adopted.
6. I4 limited to the zoo, per rebase/tag, with tolerance + re-run.
7. Fork-path inventory + all-switches-off run proves fallback = upstream.
8. Converter instead of loader patch; switch retirement rule.
9. In-run contention sampling voids contaminated runs.
10. Greedy compare capped at 32 tokens; per-model KLD references are a W0 deliverable.
