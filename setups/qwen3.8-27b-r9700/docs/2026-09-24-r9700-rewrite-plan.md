## 2. Ground truth (verified)

**Architecture** (GGUF + `qwen35.cpp:17-21`): trunk `n_layer=64`; full attention
at i=3,7,…,63 = **16 trunk FA layers** (head_dim 256, 4 KV heads), **48
Gated-DeltaNet recurrent layers**, **1 MTP layer** → **17 KV-bearing FA layers**.
16+48+1 = 65.

**Decode step @176k (~95 ms, 3.643 tok):**
- weight GEMV 22.87 GB at **582 GB/s (91% peak)** ≈ 39.3 ms — near its ceiling.
- full-attn KV 6.77 GB (17×4×256×2×1.0625 B×182889) → ~11 ms floor; FA measured
  ~**29.9 ms**, ~2.7× above floor.
- drafts: MTP has its own KV; 3 draft graphs re-read MTP block + shared LM head
  ≈ **5–6 GB**.
- CPU/command recording ~**14 ms**; small-op tail ~7.3 ms.
- Gated DeltaNet: fused op, state in registers, no workgroup barriers (clustered
  path), no coopmat; upstream RADV measured **~5%** (PR #20377), context-
  independent.
- Total ≈ **34–35 GB/step ≈ 340 GB/s**; **not bandwidth-bound** (q4_0 KV:
  38.391 vs 38.382). So any "bytes÷bandwidth" figure is a loose upper bound.

**Prefill (compute-bound):** FLOPs = 2 × 27.32e9 = **54.6 GFLOP/token**.
- pp2048 d0 = 978 t/s ≈ **53 TFLOPS** achieved (Q6_K matmul already uses the
  #27952 int8 coopmat path).
- Card class peak: R9700 ≈ 48.7 TFLOPS fp32 → ~97 TFLOPS fp16 → ~195 TOPS int8.
  So short prefill has ~2–3× compute headroom → ~2000–3000 t/s is the plausible
  band (matches an external estimate of ~3000).
- d16384 = 797 t/s ≈ 43.5 TFLOPS (attention growing); 183k ≈350 t/s
  (attention-dominated). Better attention kernels are the long-context lever.

**Constraints:** #27952 port adopted/shipped (+10% decode at 176k via acceptance).
All FA knobs closed (BR/NS/SHMEM/pipeline/f16-KV/rm_kq). Box has an intermittent
per-process low-clock mode (~20–25%); server depth.py is stable (≤0.5%); GPU
runs MUST be serialized.

## 3. Strategy

1. **Decode: FA kernel (primary).** The only large context-dependent cost, ~2.7×
   above its floor, serial/issue-bound. Restructure for ILP / fewer serial steps.
2. **Prefill: matmul + attention efficiency (large prize).** Short prefill is
   ~53 TFLOPS of a ~97–195 peak; deep prefill is attention-bound. Improve the
   int8-coopmat utilization and the prefill FA/attention tiling.
3. **CPU / command-buffer replay (~14 ms) and small-op tail (~7.3 ms).**
4. **GDN micro-opts (minor, ~5%):** state into persistent cache, fuse qkv+gate.
Out of scope: precision trades, multi-GPU, knob sweeps, context/n_max changes.

## 4. Execution model (LEAN — main orchestrates, ≤1 sub-agent TOTAL)

Cost is a hard constraint (a few days ≈ $10 already). Therefore:

- **The main session does the work.** It is the orchestrator and the primary
  engineer: it runs measurements, makes edits, builds, benchmarks, and integrates.
- **At most ONE sub-agent, used at most once**, for the single long, context-
  heavy kernel task (WS1 FA rewrite) where a fresh context is genuinely cheaper
  than paging it through the main thread. If the main session has budget, do WS1
  inline and use **zero** sub-agents.
- **No fan-out, no parallel workstreams.** The GPU is a serial resource; parallel
  agents add cost and contention with no throughput gain.
- **Order is strictly serial:** WS0 → WS1 → WS3 → WS4 → WS5. WS2 (GDN) only if
  WS1/WS3/WS4 land early and cheaply.

### WS0 — Op-budget harness (do FIRST, inline in main; ~1–2 h)
Extend `tests/test-backend-ops.cpp` with the model FA shape and GDN op shape; add
`harness/op_perf.sh` printing `op= us= spread= gbps=`. Reconcile an
op×layer-count budget (17 FA, 48 GDN, 65 FFN) against the measured 95 ms step
within 30%, and **name the top-2 contributors**. This confirms or kills the FA
hypothesis before WS1. If unreconciled, fix the harness first.

### WS1 — FA decode rewrite (the one sub-agent job; ~1–2 days)
- **Files:** `flash_attn_cm1.comp`, `flash_attn_base.glsl`, FA dispatch in
  `ggml-vulkan.cpp` (FA sections only).
- **Rewrite, not tune:** shorten the serial chain — larger KV span per iteration,
  warp-scope reductions instead of per-tile workgroup barriers, split_k with an
  out-of-kernel tree reduction; target n_rows ≤ 8, gqa_ratio 6.
- int8 coopmat FA is a NEW kernel (upstream's int8 FA is scalar and never
  dispatched on coopmat-capable devices); K-as-A is compatible with
  `mul_mmq_cm1_funcs.glsl`; Q needs quantize+pack; **PV int8 unproven** — keep PV
  float unless proven.
- **Interface:** auto-select for (q8_0 K/V, RDNA4, n_rows≤8); kill switch
  `GGML_VK_FA_NO_DECODE_V2=1`.
- **Acceptance:** WS0 FA GB/s ≥1.5×; C0 holds; 70k screen ≥50 t/s. KILL if <48.

### WS2 — Prefill efficiency (main, after WS1)
- Verify the int8 coopmat path is selected for the prefill MUL_MAT shapes; tune
  the prefill FA/attention tiling at depth; `mask_opt` packed-aware (skip fully
  masked KV blocks). No precision change.
- **Acceptance:** P0 ≥1800, P1 ≥1100, P2 ≥600.

### WS3 — Backend CPU/command-buffer replay (main, after WS1)
- Cache/replay recorded command buffers when graph topology is unchanged
  (re-recorded each submit today); reduce redundant per-token/draft syncs.
- **Acceptance:** ≥50% CPU-per-step cut (temporary `steady_clock`, removed
  before commit); outputs bit-identical; C0.

### WS4 — Small-op tail fusion (main). Tail 7.3→≤4 ms. C0.

### WS5 — Integration & final review (main)
Full gate table; full `test-backend-ops` on touched ops; greedy quality
spot-check. No separate DA pass unless something is ambiguous.

## 7. Reasoning log (why the plan changed each time)

- **rev1→rev2:** rev1 claimed FA was "15× above floor" — a per-layer floor
  compared to an all-layer cost. Removed.
- **rev2→rev3:** rev2 called >55 impossible from a ~45 t/s ceiling, assuming 65
  full-attention layers. The model is hybrid (`full_attention_interval=4`), KV is
  ~4× smaller; ceiling ~70. Retracted.
- **rev3→rev4:** rev3 over-corrected to Gated DeltaNet as the suspect; refuted by
  upstream's ~5% measurement and by GDN being context-independent. Restored FA.
- **rev4→rev5:** added the prefill analysis (compute-bound, ~53 of 97–195 peak),
  and replaced the fan-out execution with a lean single-session model because
  cost is now a first-class constraint.

**Lessons recorded:** never size a hybrid model's KV from `n_layer` alone (read
`full_attention_interval` and the model's `is_recr` logic); never infer a
bandwidth ceiling from a step proven not bandwidth-bound; measure before
rewriting.
